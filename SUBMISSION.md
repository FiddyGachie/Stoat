# Hackathon Submission Materials

## One-line description

Stoat lets autonomous agents buy and deliver software services under deterministic spending controls, verifies LLM work against evidence, accounts for obligations and reconciles real PayPal Sandbox payments.

## Short description

Agents can already perform useful work, but machine-to-machine commerce still lacks a trustworthy lifecycle. Stoat connects service discovery, structured quotes, immutable agreements, budget policy, LLM execution, deterministic delivery verification, double-entry obligations, human-approved settlement and PayPal reconciliation. Its core principle is simple: LLMs propose, deterministic code decides, evidence unlocks obligations, and humans approve settlement.

## Innovation claim (bounded)

Stoat's differentiator is not another payment rail. It is the verification and accounting context around agent commerce: grounded verification of LLM work, authority-bounded agents, an append-only economic event trail, one-obligation accounting, and explicit reconciliation between internal obligations and external payment state.

## Limitations to disclose

- PayPal Sandbox is not production payment processing.
- Provider payouts are not implemented by the MVP.
- x402/MPP adapters are not implemented unless separately evidenced.
- APIMatic / AG Studio usage depends on confirmed access.
- Hackathon MVP is not production-ready or a regulated financial service.
